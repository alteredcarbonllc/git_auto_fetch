# git_auto_fetch: историческая утилита

На рабочем VPS заменена Woodpecker и отдельными механизмами деплоя.
Не включать её параллельно новой системе. Точная серверная версия от 2026-10-05
сохранена в `historical/`; она содержит старые ограничения и не устанавливается.

## Установка и удаление
Требуются Linux, Python 3, Git, systemd, sudo (для смены пользователя).
`sudo sh install.sh` из любого каталога устанавливает в /usr/local/bin,
сохраняет существующую конфигурацию и оставляет расписание выключенным.
Старое cron-расписание этой утилиты удаляется с резервной копией.
Старый /usr/bin/git_auto_fetch.sh при установке сохраняется: внешние ссылки надо проверить отдельно.
Makefile вызывает тот же установщик. .env больше не используется.
На Devuan эти systemd-установщики не применять: это исторический компонент VPS.

Только при осознанном возвращении старой системы: настроить /etc/git_auto_fetch.conf,
затем `sudo systemctl enable --now git_auto_fetch.timer`.
Удаление: `sudo sh uninstall.sh`; с конфигурацией: `sudo sh uninstall.sh --purge`.
Удаление сохраняет копии в /var/backups, не удаляет пользователя git, репозитории,
логи, sudoers или Git daemon. Общий cron не перезапускается.

## Поведение
Единая блокировка /run/lock/git_auto_fetch.lock; повторный запуск пропускается.
Git-команды ограничены 180 секундами; ввод паролей отключён.
Ошибки отдельных репозиториев не мешают проверке остальных, итоговый код — 1.
Вывод идёт в stdout/stderr (journal при запуске службой).
`--config` и `--lock` позволяют изолированные проверки без /etc и /run.

Fetch не меняет рабочие файлы. Конфигурация — абсолютные пути, по одному
на строку. Выполнение от пользователя службы (по умолчанию root).

## Проверка
`python3 -m unittest discover -s tests -v` — локальные временные Git-репозитории.
Уведомления в реальные сервисы тесты не отправляют.
